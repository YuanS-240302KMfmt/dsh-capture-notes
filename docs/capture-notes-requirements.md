# dsh-capture-notes 需求文档（v1）

> 文档状态：**需求冻结 v1.2**（2026-11-08，Q1–Q10 全部决议）
> 本轮范围：只明确需求与验收，不做实现。
> 中文显示名：**录屏字幕台**
> 目标产物：`<仓库目录>`（新模块，尚未创建）
> 参考对象：`live-translate`、`.video-notes`（**只读参考，不改动**）

---

## 0. 一句话定义

一个 Windows 桌面小窗模块：**实时 / 录屏 / 文件**三种模式共用同一套「采集 → VAD → 识别 →（翻译）→ 字幕 / 逐字稿」引擎，所有会话与文件产物按统一目录落盘；实时译文走内置 translator，文件模式译文与纪要在对话里按需由 agent 生成。

## 1. 已确认决策

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 模块定位 | **双入口同等**：实时链路与离线（文件）链路都是一等功能 |
| 2 | 与旧模块关系 | **独立新模块**；两个旧模块只作参考，不修改、不接管其插件 id 与输出目录 |
| 3 | 说话人区分 | **不进 v1**，放到 P1；v1 用「系统 / 麦克风」双路作为天然的两人先验 |
| 4 | 交付物 | 实时字幕小窗、逐字稿 MD/SRT、按需纪要、软/硬字幕成片、会话录音归档、统一产物目录，另加**录屏按钮** |
| 5 | 硬约束 | 无 GPU（纯 CPU）、实时（p95 ≤ 2.5 s）、任意临时说话人、不录声纹、多语言且日文优先、仅 Windows 桌面 |
| 6 | 录屏范围 | **整个屏幕**（多显示器时可选显示器）；同时录系统声音与麦克风，**两条音轨分开** |
| 7 | 录屏与字幕 | **同一次会话**：录屏时照常出实时字幕，共享时间轴、共享音频归档 |
| 8 | 运行时与模型 | **完全自带一份**（模型 + sherpa-onnx + ffmpeg），不依赖旧目录 |
| 9 | 纪要生成 | **只存逐字稿，按需生成**（不在停止时自动烧 token） |
| 10 | 界面形态 | **单小窗三模式**：实时 / 录屏 / 文件 |
| 11 | 实时音源 | **支持双路识别，也可只跑一路**（系统 / 麦克风 / 两者） |
| 12 | 录屏格式 | **MP4（H.264）+ 两条独立音轨（系统、麦克风）+ 16 kHz 单声道 WAV 分轨** |
| 13 | 模块命名 | `dsh-capture-notes`，目录 `<仓库目录>` |
| 14 | 文件模式默认 | 逐字稿 + **软字幕成片**；硬字幕为高级选项；译文按需由 agent 生成 |
| 15 | 文件模式译文 | **由 agent 生成**（对话中触发），模块不内置 MT，只负责校验、落盘与封装 |
| 16 | 录屏后处理 | 停止后**弹窗询问**；同意则一键对录屏产物跑文件模式的字幕/成片流程 |
| 17 | 其余细节 | 不做暂停、不做历史列表、支持多显示器选择、P1 复用双路先验、中文名「录屏字幕台」、支持只抽内嵌字幕 |
| 18 | 译文形态 | 文件模式译文**默认双语**（原文上、译文下），可选单语 |

## 2. 场景与用户故事

### 2.1 实时看直播 / 视频（日文优先）

> 我在看一场日文直播，希望屏幕上有一个不挡内容的小窗，实时显示日文原文和中文译文，并标明这句来自电脑声音还是我的麦克风。

- 只勾「系统音频」，字幕来源徽标为「系统」。
- 停止后自动落逐字稿与 SRT，之后可以让人写纪要。

### 2.2 线上会议（双路）

> 会议里对方的声音从电脑出来，我说话走麦克风；我要两路都能出字幕，并且分得清哪句是对方、哪句是我。

- 勾选双路，系统与麦克风分别 VAD、分别识别，字幕按来源分行/加徽标。
- 会话结束归档两路 WAV，供以后 P1 做说话人聚类与离线精修。

### 2.3 录屏讲解 / 课程

> 我要把整个屏幕的操作过程录下来，同时把讲解实时转成字幕；录完得到一个 MP4，系统声和麦克风是两条独立音轨，方便后期。

- 点「● 录制」开始：全屏画面 + 双音轨 + 实时字幕。
- 停止后得到 `screen.mp4`（双音轨）、两路 WAV、逐字稿。
- 停止时弹窗：「是否给这段录屏加字幕？」→ 软字幕 / 硬字幕 / 仅字幕文件 / 取消；同意即一键跑文件模式后处理，产出 `screen.soft.mp4` 或 `screen.hardsub.mp4`。

### 2.4 已有视频 → 逐字稿 / 字幕成片

> 我有一个已经录好的视频，想要逐字稿和一条能直接看的软字幕成片；需要烧录时再选硬字幕。

- 文件模式选择文件 → 抽音 → 识别 → 逐字稿 + `*.soft.mp4`。
- 可选硬字幕，提示耗时与画质损失。
- 需要译文时，在对话里让 agent 按 `segments.json` 逐段翻译；模块校验后用译文重建字幕与成片（默认双语，可选单语）。

### 2.5 会后整理

> 录完一小时的会议，我只要说一句「给最近这次录制出纪要」。

- 技能读取最近会话的 `transcript.md` / `segments.json`，写 `notes.md`（简体、带时间戳、按模板）。

## 3. 范围

### 3.1 v1 范围内

- 系统音频 / 麦克风采集，双路可同时、可只跑一路。
- 实时双语字幕（原文 + 译文），来源标注，独立小窗 + 托盘。
- 全屏录屏，MP4 + 双音轨 + WAV 分轨，与实时字幕同会话。
- 本地视频/音频文件 → 逐字稿 + 软字幕成片（硬字幕可选）。
- 文件模式译文：由 agent 生成结构化译文，模块负责校验与封装（默认双语字幕，可选单语；可重建软/硬成片）。
- 录屏结束后可一键对录屏产物加字幕成片。
- 统一会话目录与产物清单；会话 JSON 清单。
- 按需纪要（技能，读取会话产物）。
- 自带模型与运行时；不依赖旧模块目录。

### 3.2 明确不做（v1）

| 不做 | 说明 / 去向 |
|---|---|
| 说话人聚类与重叠标记 | P1，见 `docs/live-translate-video-notes-integration-design.md` |
| 重叠语音分离（MossFormer2 等） | P1 / 离线精修，不进入实时链路 |
| 声纹注册、目标说话人提取 | 硬约束排除 |
| 说话人真实身份识别 | 只区分通道/编号，不猜「这是谁」 |
| TTS 配音 | 不做 |
| 区域框选录制、指定窗口录制 | v1 只做全屏（可多显示器选择） |
| 在线链接（URL）输入 | v1 只支持本地文件；需要时后续加 yt-dlp |
| macOS / Linux | 仅 Windows 10/11 |
| 云端转写 / 云端 diarization | 不做；翻译仍是可选的联网环节 |
| 实时把字幕叠加进录屏画面 | v1 不做；改为录屏结束后弹窗，一键事后加字幕（软/硬） |
| 录屏暂停 / 继续 | v1 只做开始 / 停止 |
| 窗口内会话历史列表 | v1 不做；只提供「打开输出目录」与技能按 id 定位 |
| 多实例并发处理 | 单实例 + 任务队列，避免模型互抢 |

## 4. 功能需求

编号规则：`FR-<域><序号>`。优先级均为 v1 必须，除非标注「可选」。

### 4.1 采集（FR-C）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-C1 | 捕获默认播放设备的系统音频（WASAPI loopback），无需虚拟声卡 | 播放任意音频即可产生 PCM；无活动音频会话时给出提示 |
| FR-C2 | 捕获默认/指定麦克风 | 设备列表来自系统；热插拔后可在设置里重选 |
| FR-C3 | 双路可同时采集，也支持只开系统或只开麦克风 | UI 至少勾选一路；只开一路时字幕不出现另一路内容 |
| FR-C4 | 两路各自独立的时间轴与音量归一化，互不串音 | 静音麦克风时，麦克风路无字幕；系统路不受影响 |
| FR-C5 | 每路同时产出两种数据：低延迟识别流（16 kHz 单声道）与归档音轨（原始采样率/声道） | 识别延迟与归档质量互不牺牲 |
| FR-C6 | 采集异常（设备被占用、驱动无响应、无音频会话）可检测并提示，不崩溃 | 提示含具体设备名与原因 |
| FR-C7 | 会话结束或崩溃后，已写入的归档音频可被识别/播放 | 见 FR-R6 |

### 4.2 实时模式（FR-L）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-L1 | 开始/停止会话；首次加载模型显示「正在加载」，之后常驻复用 | 二次开始 ≤ 1 s 进入监听 |
| FR-L2 | 双语字幕：原文一行、译文一行；译文失败时保留原文并标注状态 | 断网时字幕不中断 |
| FR-L3 | 双路时每行带来源徽标（系统 / 麦克风）；单路时可不显示 | 徽标与实际音源一致 |
| FR-L4 | 源语言 `auto/zh/en/ja/ko/yue`，目标语言 `zh-CN/zh-TW/en/ja/ko/fr/de/es/ru`；记住上次选择 | 重启后保持上次语言对 |
| FR-L5 | 约 0.9 s 刷新临时字幕；VAD 断句后替换为最终字幕 | 临时字幕不重复、不回退 |
| FR-L6 | 停止后自动保存 `transcript.md`（段落 + 时间戳 + 译文）与 `transcript.srt` | 与窗口内容一致，时间戳单调递增 |
| FR-L7 | 无音频超过设定时长（默认 180 s）自动停止并保存 | 不丢已识别内容 |
| FR-L8 | 翻译 provider `auto/bing/google`，失败自动回退、保留原文 | 单段翻译超时不阻塞后续 |
| FR-L9 | 字幕行数上限（默认 200 行）后滚动淘汰，不无限占内存 | 长会话内存稳定 |

### 4.3 录屏模式（FR-R）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-R1 | 窗口内常驻「● 录制」入口；录制目标为整个屏幕，多显示器时下拉选择（默认主屏） | 录制中显示红点与计时 |
| FR-R2 | 系统声音与麦克风录成**两条独立音轨** | 播放器可分别切换/静音两条音轨 |
| FR-R3 | 录制与实时字幕同一次会话：字幕、语言、翻译设置与实时模式一致 | 停止后字幕与录屏时间轴对齐 |
| FR-R4 | 视频编码 H.264，默认 1080p / 30 fps；码率/帧率/分辨率可配置 | 默认档位 1 小时 ≤ 1.6 GB |
| FR-R5 | 停止后完成 MP4 封装，产出可直接播放的文件 | 停止到可播 ≤ 30 s（10 分钟素材） |
| FR-R6 | 崩溃/断电后，已写入的片段可恢复为可播放视频或可识别音频，不产生「全是 0 字节」的目录 | 强杀进程后重启，会话标记为「未正常结束」并可修复 |
| FR-R7 | 录制前检查磁盘剩余空间（默认要求 ≥ 预估大小 × 1.5），不足则拒绝开始 | 提示含预估大小与剩余空间 |
| FR-R8 | 录制中允许停止；v1 不支持暂停/继续 | 停止后所有轨道时长一致（误差 ≤ 200 ms） |
| FR-R9 | 停止并封装完成后弹窗询问是否加字幕：软字幕 / 硬字幕 / 仅字幕文件 / 取消 | 选择后一键进入文件模式后处理，无需重新选文件 |
| FR-R10 | 后处理默认复用本会话 `segments.json`（时间轴一致），可勾选「重新识别」 | 复用时不重复识别；重新识别时按文件模式全流程执行 |
| FR-R11 | 后处理产物写回会话目录（`screen.soft.mp4` / `screen.hardsub.mp4` / `screen.srt`），并更新 `session.json` | 不产生第二个会话目录 |

> **技术风险**：屏幕捕获 + 双音轨封装是 v1 最高风险项。候选实现是「画面用 ffmpeg 录成无音轨 MP4，音频用 NAudio 写两路 WAV，停止后一次性封装」，需在 P0 做技术验证；若不可行，降级顺序为「MKV 双音轨 → MP4 单音轨 + 两路 WAV」。

### 4.4 文件模式（FR-F）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-F1 | 选择一个本地视频或音频文件 | 支持 mp4/mkv/mov/avi/webm/mp3/wav/m4a/flac |
| FR-F2 | 抽音 → VAD 断句 → SenseVoice 识别；语言可选 | 无音轨时明确报错，不产生空纪要 |
| FR-F3 | 产出逐字稿 `transcript.md`、`transcript.srt`、`segments.json`、纯文本 `transcript.txt` | 中文统一简体；时间戳与音轨一致 |
| FR-F4 | 默认产出软字幕成片 `*.soft.mp4`；字幕轨可开关 | 成片时长与源一致，视频流不重编码 |
| FR-F5 | 硬字幕为高级选项；提示耗时（约 6–12 分钟/小时）与画质损失 | 烧录后成片无字幕轨 |
| FR-F6 | 显示分阶段进度（抽音 / 识别 / 字幕 / 封装 / 烧录）与可取消 | 取消后不残留半成品在 `out` |
| FR-F7 | 可调：语言、字幕形态、字体、底部边距、是否保留音频 | 默认：简体、软字幕、微软雅黑、边距 5% |
| FR-F8 | 同一内核提供无界面 CLI，供技能与批处理调用 | CLI 与 GUI 产物一致 |
| FR-F9 | 处理中禁止同时启动第二个文件任务；实时/录屏任务进行中时提示冲突 | 模型串行加载，不出现两套模型抢 CPU |
| FR-F10 | 支持「只抽内嵌字幕、不跑 ASR」（高级选项） | 有文本字幕轨时秒级完成；无字幕轨时明确报错 |
| FR-F11 | 产出可供 agent 翻译的结构化文件（`segments.json` + 会话语言信息），**不在模块内调用 LLM** | 字段完整、可被技能直接读取 |
| FR-F12 | 提供 CLI：校验 agent 译文并按段对齐，默认生成 `transcript.bi.srt`（双语）与 `transcript.<target>.md`，可选 `transcript.<target>.srt`（单语），可据此重建软/硬字幕成片 | id 缺失/多余/重复时报错并列出；成功后可播放双语字幕 |

### 4.5 译文与纪要（agent 协作）

#### 4.5.1 译文（FR-T）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-T1 | 文件模式不内置机器翻译（实时模式仍走内置 translator）；文件译文由 agent 在对话中生成 | 模块内无文件 MT 依赖；断网也能出原文 |
| FR-T2 | agent 读 `segments.json`，按 id 逐段翻译，写 `translation.<target>.json`（见 5.3） | 不新增/删除/合并段落；只填译文 |
| FR-T3 | 译文默认生成**双语字幕**（原文在上、译文在下）；可选目标语言单语字幕 | 双语每条 cue 最多两行（原文、译文各一行）；单语/双语共用同一份译文数据，不重复翻译 |
| FR-T4 | 译文可重建软字幕成片或烧录硬字幕，流程与原文一致 | 重建后时间轴、时长不变 |
| FR-T5 | 小窗只显示译文状态（未生成 / 已生成 / 已封装），v1 不提供「生成译文」按钮 | 入口在对话，避免窗口调度 agent |

#### 4.5.2 纪要（FR-N）

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-N1 | 会话目录与文件模式产物都包含足够信息：时间戳、逐字稿、语言、来源 | 技能无需读音频即可写纪要 |
| FR-N2 | 纪要由技能在对话中按需生成，模块本身不调用大模型、不自动消耗 token | 停止后不自动生成 notes.md |
| FR-N3 | 纪要必须简体、带 `[HH:MM:SS]` 时间戳、按会议/课程/访谈模板组织 | 人工抽查无繁体、无编造 |
| FR-N4 | 技能能定位「最近一次会话」，也接受指定会话 id/路径 | 多会话时能选对 |
| FR-N5 | 纪要写回会话目录（`notes.md`），不覆盖逐字稿 | 生成后逐字稿字节不变 |

### 4.6 产物与目录（FR-O）

```
<仓库目录>\
  sessions\
    <YYYYMMDD-HHmmss>-<shortid>\
      session.json          # 会话清单（见第 5 节）
      screen.mp4            # 录屏模式
      audio\
        system.wav          # 系统声音归档（原始采样率/声道）
        mic.wav             # 麦克风归档
      transcript.md         # 段落稿（原文 + 译文）
      transcript.srt
      segments.json
      translation.<target>.json  # agent 译文（按需）
      transcript.bi.srt          # 双语字幕（默认形态，按需）
      transcript.<target>.srt    # 单语译文字幕（可选）
      screen.soft.mp4       # 录屏后处理：软字幕成片（按需）
      screen.hardsub.mp4    # 录屏后处理：硬字幕成片（按需）
      notes.md              # 按需生成
  work\<slug>\              # 文件模式中间产物（audio.wav、segments.json…）
  out\<slug>\               # 文件模式交付物（session.json、逐字稿、译文、*.soft.mp4、*.hardsub.mp4、notes.md）
  config\                   # 用户设置（非凭据）
```

| 编号 | 需求 |
|---|---|
| FR-O1 | 会话 id 为本地时间 + 4 位短随机串，目录名不含空格与非法字符 |
| FR-O2 | `session.json` 在会话开始即创建，随状态增量更新；崩溃后仍可读 |
| FR-O3 | 产物路径写入 `session.json`，窗口可「打开所在文件夹」 |
| FR-O4 | 文件模式 `work` 可一键清空，`out` 不受影响 |
| FR-O5 | 默认保留所有会话；提供「清理 30 天前会话」手动操作（不自动删） |

### 4.7 小窗与交互（FR-U）

| 编号 | 需求 |
|---|---|

## 5. 数据契约

### 5.1 `session.json`

```json
{
  "schema": 1,
  "id": "20261108-142500-a1b2",
  "mode": "live",
  "status": "completed",
  "createdAt": "2026-11-08T14:25:00+08:00",
  "endedAt": "2026-11-08T15:10:12+08:00",
  "languages": { "source": "ja", "target": "zh-CN" },
  "sources": { "system": true, "mic": true },
  "input": { "kind": "device" },
  "recording": {
    "video": "screen.mp4",
    "tracks": [
      { "role": "system", "file": "audio/system.wav", "sampleRate": 48000, "channels": 2 },
      { "role": "mic", "file": "audio/mic.wav", "sampleRate": 48000, "channels": 1 }
    ]
  },
  "artifacts": {
    "transcript": "transcript.md",
    "srt": "transcript.srt",
    "segments": "segments.json",
    "translations": [],
    "subtitledVideo": null,
    "notes": null
  },
  "stats": { "segments": 412, "durationSec": 2712.4, "rtf": 0.04 },
  "crashRecovered": false
}
```

- `mode`：`live` | `record` | `file`。
- `status`：`starting` | `listening` | `recording` | `stopping` | `completed` | `aborted` | `error`。
- 文件模式额外有 `input.kind: "file"` 与 `input.path`、`input.sha256`；此时 `session.json` 写在 `out\<slug>\`，`work\<slug>\` 只放中间产物。
- `artifacts.translations`：`[{ "target": "zh-CN", "file": "translation.zh-CN.json", "state": "generated" }]`，未生成时为空数组。
- `artifacts.subtitledVideo`：录屏后处理产物（`screen.soft.mp4` / `screen.hardsub.mp4`），未处理时为 `null`。

### 5.2 `segments.json` / 单条 Segment

```json
{
  "id": "s000123",
  "start": 12.34,
  "end": 15.67,
  "text": "……",
  "lang": "ja",
  "source": "system",
  "speaker": null,
  "speakers": [],
  "overlap": false,
  "translation": "……",
  "translationState": "done"
}
```

- `source`：`system` | `mic` | `file`。
- `speaker` / `speakers` / `overlap` **v1 恒为空/false，字段保留**，P1 填充且不破坏兼容。
- `translationState`：`none` | `pending` | `done` | `error` | `same`。

### 5.3 `translation.<target>.json`

```json
{
  "schema": 1,
  "target": "zh-CN",
  "source": "segments.json",
  "createdAt": "2026-11-08T16:02:00+08:00",
  "segments": [
    { "id": "s000123", "text": "……" }
  ]
}
```

- `id` 必须与 `segments.json` 一一对应；不允许合并、拆分、增删段落。
- 只写译文，不写原文；原文永远以 `segments.json` 为准。
- 校验规则：缺失 id / 多余 id / 重复 id 均视为失败，CLI 报错并列出差异。
- 同一会话可有多个目标语言，文件名带 target 区分。

### 5.4 兼容约束

- 字段只增不改；消费方必须忽略未知字段。
- 时间单位一律秒（浮点），时区一律本地时间带偏移。
- 与设计文档第 6 节 schema 保持同名同义，便于 P1 直接升级。

## 6. 非功能需求

### 6.1 性能（本机：Core Ultra 5 125H，18 线程，无独显）

| 指标 | 目标 | 说明 |
|---|---|---|
| 端到端字幕延迟（语音停顿 → 字幕） | p95 ≤ 2.5 s | 双路 + 录屏同时进行时 p95 ≤ 3.0 s |
| 临时字幕刷新 | ≤ 1.2 s | 双路各算 |
| 模型加载 | ≤ 3 s | 会话内复用 |
| 单路 ASR RTF | ≤ 0.10 | 现基线 ≈ 0.03 |
| 双路 ASR 合计 RTF | ≤ 0.20 | 不含录屏编码 |
| 文件模式 RTF（1080p 视频） | ≤ 0.15 | 不含硬字幕烧录 |
| 录屏 CPU 占用 | 空闲核心可跑满 1080p30 | 与双路 ASR 并发不互相饿死 |
| 录制音画偏差 | ≤ 200 ms | 以拍手/计时器抽检 |
| 内存峰值 | ≤ 1.5 GB | 4 小时会话不持续增长 |

### 6.2 稳定性与恢复

- 连续 60 分钟实时/录屏会话不崩溃、不丢字幕。
- 强杀进程后：`session.json` 可读，已写 WAV 可识别，视频可修复或明确标记不可用。
- 单实例：同一时间只允许一个采集会话；文件任务与采集任务互斥。
- 网络异常：翻译失败降级为原文，不阻塞识别与保存。

### 6.3 隐私与安全

- 音频、视频、逐字稿只落本机；不上传任何媒体。
- 实时翻译会把**文本**发往 Bing/Google 匿名端点；设置里需明示，并支持「只识别不翻译」。
- 文件模式译文由 agent 生成，逐字稿文本会进入对话上下文/模型；技能需在动手前告知，用户可拒绝。
- 不采集、不保存声纹；P1 的说话人 embedding 只在内存中用于聚类，不落盘。
- 不读写 DSH 凭据；`config\` 只存非敏感设置。

### 6.4 兼容与环境

- Windows 10 2004+ / Windows 11，x64。
- PowerShell 7（pwsh）优先；5.1 下需有明确降级提示（NAudio `Add-Type` 可能失败）。
- 无需管理员权限；无需虚拟声卡。
- 自带：SenseVoice int8（约 229 MB）、Silero VAD（约 0.6 MB）、sherpa-onnx 运行时、ffmpeg/ffprobe（合计约 400 MB）。
- 模块目录可整体搬迁；路径不存在时给出明确提示，不静默失败。

### 6.5 国际化与文案

- UI 中英双语（`locale/zh.json`、`locale/en.json`，沿用现有插件格式）；中文标题「录屏字幕台」。
- 文案边界（与设计文档一致）：说「支持说话人区分（P1）」「重叠会标注」，不说「同时说话自动分离」。
- 所有错误信息包含：发生了什么、影响范围、下一步怎么做。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 屏幕捕获 + 双音轨封装难落地 | 录屏功能延期或降级 | P0 先做 PoC；降级顺序 MP4 双轨 → MKV 双轨 → MP4 单轨 + WAV 分轨 |
| 全屏 1080p30 编码吃 CPU，与双路 ASR 抢核 | 字幕延迟尖峰、丢帧 | 限制 ASR 线程；录屏降档；必要时硬件编码 |
| 双路 ASR 内存/句柄翻倍 | 长会话不稳定 | 单进程双流或两个 worker 需实测；限制并发 |
| 自带运行时约 400 MB | 安装/升级体积大、复制慢 | 整包版本化；提供校验与「运行时缺失」自检 |
| PowerShell 7 依赖 | 5.1 下窗口起不来 | 启动前检测并给出安装指引；保留 `-Diagnose` |
| 长会话磁盘写满 | 录制中断、文件损坏 | 开录前预估 + 运行中周期检查（如每 60 s） |
| 翻译需联网 | 断网无译文 | 保留原文；明示「翻译不可用」 |
| 实时与文件任务同时加载模型 | 内存翻倍、延迟抖动 | 单实例互斥 + 队列 |
| 独立模块与旧模块功能重叠 | 用户混淆、维护两份 | 明确定位：新模块是新能力（录屏/双路/纪要闭环）；旧模块保持现状 |
